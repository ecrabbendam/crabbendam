The team conducted a live walkthrough of the Arisoft-built label printing and disposition web application against the Schneider IQMS/DelmiaWorks environment. The session uncovered that the application had never fully functioned end-to-end in the client's environment — errors existed from the beginning but had not been surfaced until today's deep-dive. A total of nine issues were catalogued ranging from data correctness bugs (gross vs. net weight) to blocking infrastructure problems (IQMS Web API not posting disposition transactions). By the end of the meeting, one critical blocker (missing TRANSCODE configuration) was identified as a likely root cause of failed disposition, but full resolution requires further API-level investigation with Schneider's IT and IQMS support team.

Key agreed findings

Blocking

Disposition not posting to IQMS

The app creates a label record (serial number) but fails to write disposition data or lot info to the master label record. The Web API returns an error — root cause is likely a missing TRANSCODE inventory parameter in IQMS and possibly an incomplete Web API installation.

Blocking

API error is API-level, not IIS-level

Ovais (IT) confirmed IIS itself is operating correctly. The error is coming from within the IQMS Web API layer. Waqas and Ovais need to run Postman tests to isolate the exact failing call and involve the IQMS Web API support team.

Design gap

Work center must be dynamic

The current select-line dropdown uses hard-coded values. The correct design pulls the work center from the scheduled work order via the CNTSCH table joined to the work center table — matching how Delmia and ShopData already behave.

Data bug

Quantity shows gross, not net weight

The label is pulling gross weight instead of net weight. Both the serial number quantity and the transaction quantity fields are affected. Fix is confirmed straightforward but must be deployed.

Policy

Serial number alignment opportunity

Janeczka believes internal IQMS serial number and Arisoft barcode serial number can be made the same value, eliminating friction for floor workers who currently need both. She will seek written approval from Jolene to simplify this.

Config

Hard-coded values to move to web.config

Several values (including the location and line type) are currently hard-coded in the app. Taz agreed these should be moved to a web config file for maintainability and environment-specific control.
