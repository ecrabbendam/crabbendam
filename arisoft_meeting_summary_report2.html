Architecture
The session uncovered that the application had never fully functioned end-to-end in the client's environment. A total of nine issues were catalogued, ranging from data correctness bugs to blocking infrastructure problems.

Key Agreed Findings

Blocking

Disposition not posting to IQMS

The app creates a label record (serial number) but fails to write disposition data or lot info to the master label record. Root cause is likely a missing TRANSCODE inventory parameter.

Blocking

API error is API-level, not IIS-level

Ovais (IT) confirmed IIS is operating correctly. The error is within the IQMS Web API layer; Postman tests are required to isolate the failing call.

Design Gap

Work center must be dynamic

The dropdown uses hard-coded values. The correct design must pull from the scheduled work order via the CNTSCH table.

Data Bug

Quantity shows gross, not net weight

Labels are pulling gross weight (e.g. 1220) instead of net weight (e.g. 1000) for both serial number and transaction fields.

Policy

Serial number alignment opportunity

Janeczka Lee proposes unifying the internal IQMS serial number and Arisoft barcode to eliminate operator friction.

Config

Hard-coded values to move to web.config

Location and line type values currently in code must move to the web.config file for environment-specific control.
